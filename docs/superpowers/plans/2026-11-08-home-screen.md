# Home Screen Implementation Plan

> **Для самостоятельной разработки:** выполняй задачи последовательно в Android Studio. Не копируй весь код вслепую: сначала разбери объяснение шага, напиши код самостоятельно, затем проверь результат и при необходимости попроси наставника о ревью.

**Цель:** заменить стартовый экран-приветствие минималистичным главным экраном лаунчера с часами, датой и пятью временными иконками.

**Архитектура:** Compose отвечает за отображение. `HomeViewModel` формирует состояние и публикует его через `StateFlow`. `MainActivity` связывает ViewModel с экраном. Android Manifest объявляет Activity доступной как Home Launcher.

**Технологии:** Kotlin, Jetpack Compose, Material 3, AndroidX Lifecycle, StateFlow, java.time.

**Спецификация:** `docs/superpowers/specs/2026-11-08-home-screen-design.md`

## Глобальные ограничения

- Минимальная версия Android: API 26.
- Сохранить существующий пакет `com.example.minimallauncher` и текущую Compose-тему.
- Не добавлять Room или DataStore на этом этапе.
- Не добавлять сторонние библиотеки для часов, даты или иконок.
- Все изменения кода пользователь выполняет самостоятельно; наставник объясняет, проверяет и помогает исправлять ошибки.

## Структура файлов

- Создать `app/src/main/java/com/example/minimallauncher/launcher/home/HomeUiState.kt` — неизменяемая модель состояния экрана.
- Создать `app/src/main/java/com/example/minimallauncher/launcher/home/HomeViewModel.kt` — обновление времени и даты, публикация состояния через StateFlow.
- Создать `app/src/main/java/com/example/minimallauncher/launcher/home/HomeScreen.kt` — только Compose UI для часов, даты и пяти заглушек.
- Изменить `app/src/main/java/com/example/minimallauncher/MainActivity.kt` — получить ViewModel и отобразить HomeScreen вместо Greeting.
- Изменить `app/src/main/AndroidManifest.xml` — добавить HOME и DEFAULT категории к существующему MAIN intent-filter, сохранив LAUNCHER.
- Изменить `gradle/libs.versions.toml` и `app/build.gradle.kts` — добавить только необходимые AndroidX Lifecycle зависимости для ViewModel и lifecycle-aware collection.

## Review Focus

- Смена системного времени или часового пояса — время и дата должны соответствовать системным настройкам.
- Переход через полночь — дата должна обновиться без перезапуска приложения.
- Длинная локализованная дата — текст не должен ломать композицию.
- Разные размеры экрана и системные панели — ряд иконок остаётся видимым, контент не перекрывается.
- Выбор приложения Home — система должна предлагать Minimal Launcher наряду с другими лаунчерами.

### Task 1: Подготовить состояние и ViewModel

**Файлы:**
- Создать: `launcher/home/HomeUiState.kt`
- Создать: `launcher/home/HomeViewModel.kt`
- Изменить: `gradle/libs.versions.toml`
- Изменить: `app/build.gradle.kts`

**Результат:** ViewModel публикует текущее время, локализованную дату и пять временных элементов через StateFlow.

- [ ] Разобраться, зачем UI отделяют от состояния и что такое StateFlow.
- [ ] Добавить необходимые AndroidX Lifecycle зависимости через Version Catalog; не подключать лишние библиотеки.
- [ ] Создать `HomeUiState` с полями для отображаемого времени, даты и списка пяти заглушек.
- [ ] Создать `HomeViewModel`, который каждую секунду обновляет время и дату с учётом системной локали и часового пояса.
- [ ] Проверить Gradle Sync и выполнить Build > Make Project.

### Task 2: Создать Compose экран

**Файлы:**
- Создать: `launcher/home/HomeScreen.kt`

**Интерфейс:**
- `HomeScreen(uiState: HomeUiState, modifier: Modifier = Modifier)`

**Результат:** экран отображает крупные часы, дату и пять одинаково распределённых временных иконок в нижней части.

- [ ] Создать экран с вертикальной компоновкой на всю доступную площадь.
- [ ] Добавить часы и дату, используя значения из uiState; не вычислять время непосредственно внутри Composable.
- [ ] Добавить пять временных иконок-заглушек в горизонтальном ряду с равномерным распределением.
- [ ] Оставить свободное пространство между блоком даты и нижним рядом.
- [ ] Проверить экран через Preview или запуск приложения после подключения в Task 3.

### Task 3: Подключить ViewModel и зарегистрировать Home Launcher

**Файлы:**
- Изменить: `MainActivity.kt`
- Изменить: `AndroidManifest.xml`

**Результат:** приложение показывает новый экран и появляется в системном выборе приложения Home.

- [ ] Получить `HomeViewModel` из Activity с помощью AndroidX ViewModel.
- [ ] Собрать StateFlow в Compose с учётом жизненного цикла Activity.
- [ ] Заменить Greeting на HomeScreen, передав ему текущее состояние.
- [ ] Добавить `CATEGORY_HOME` и `CATEGORY_DEFAULT` к MAIN intent-filter; сохранить `CATEGORY_LAUNCHER`, чтобы приложение также запускалось из списка приложений.
- [ ] Собрать и запустить приложение.
- [ ] Открыть системный выбор приложения Home и проверить, что Minimal Launcher там присутствует; пока не обязательно назначать его приложением по умолчанию.
